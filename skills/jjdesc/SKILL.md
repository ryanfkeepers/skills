# jjdesc

Write a `jj describe` message for a revision.

## Step 1 — Get the diff

Always operate on the working-copy change:

```
jj diff --no-pager
jj log -r @ --no-pager
```

## Step 2 — Classify changed files

Split the changed files into three buckets:

- **Autogenerated** — `*.pb.go`, `*_gen.go`, `*.generated.*`,
  `go.sum`, `package-lock.json`, `yarn.lock`, files whose first
  line contains `// Code generated` or `# generated by`
- **Docs** — `*.md`, `*.rst`, anything under `docs/`
- **Code** — everything else

**If only docs or autogenerated files changed**, describe those changes
directly (do not skip them).

**If code files changed**, ignore autogenerated and doc files when
writing the description.

## Step 3 — Establish the goal

The description should explain changes *in context of the overall goal*.

If the goal has not already been provided in this conversation, ask:

> "What is the overall goal of this change?"

Do not proceed to Step 4 until you know the goal.

## Step 4 — Write the description

Format:

```
<subject line>

<paragraph 1>

<paragraph 2>
```

Rules:

- **Subject line**: one short imperative phrase stating the goal,
  e.g. `add retry logic to the ingestion client`. No period.
  Maximum ~72 characters.
- **Paragraph 1**: what changed and why, in context of the goal.
  Two or three sentences max.
- **Paragraph 2**: notable details about the end state of the code —
  anything a reviewer needs to understand that isn't obvious from the
  diff. Do not describe planning decisions, tradeoffs considered, or
  alternatives rejected. Omit if there is nothing worth saying.
- Do not describe doc or autogenerated changes if code changed.
- Do not pad with filler like "This commit..." or "This PR...".

Voice example:

> add retry logic to the ingestion client
>
> The ingestion client now retries transient HTTP 5xx responses with
> exponential backoff (max 3 attempts). This unblocks intermittent
> failures caused by upstream throttling.
>
> Retry state is tracked per-request, not per-client, so concurrent
> calls do not share backoff state.

Counter-example (avoid):

> Update files
>
> This commit updates several files to add some retry logic and also
> fixes some docs. Various improvements were made.

## Step 5 — Apply

Run immediately:

```
jj describe -m "<description>"
```
